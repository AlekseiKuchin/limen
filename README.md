# Лимен

Независимый статистический аудит автоматического закрытия алертов в SOC.

Часть алертов в SOC закрывается без аналитика: ИИ вендора, плейбуки SOAR, правила подавления. «Лимен» проверяет такую автоматизацию по выгрузке уже закрытых алертов. Он отбирает небольшую случайную выборку автозакрытых алертов, аналитики заказчика перепроверяют её как при обычном разборе, а «Лимен» считает верхние границы двух величин — по всему потоку и по каждому правилу:

- **доля атак среди автозакрытых алертов** (FOR, false omission rate);
- **доля атак, закрытых автоматикой, среди всех атак периода** (FNR, false negative rate).

Пример: перепроверено 300 случайных алертов из 12 400 автозакрытых, атак не найдено. С уверенностью 95% доля атак среди автозакрытых не больше 0,99%, то есть среди них не больше 123 атак.

Гарантия держится на случайном отборе по плану, зафиксированному до разметки, а не на предположениях о модели вендора. Методика — [docs/methodology.md](docs/methodology.md).

## Принципы версии 0.2

- **Офлайн и нулевое доверие.** Ядро не ходит в сеть и не открывает портов. Файлы на границе контура проверяются по SHA-256, результат пересчитывается командой `limen verify` ([docs/zero-trust.md](docs/zero-trust.md)).
- **Сборка из исходников.** Зависимости ядра компилируются из исходных дистрибутивов с проверкой хешей, Trivy — из тега исходного кода ([ADR 0003](docs/adr/0003-build-from-source.md)).
- **Стек из курсов DevOps, DevSecOps и MLOps.** Инструменты вне курсов помечены как вариант ([docs/stack.md](docs/stack.md)). В ядре пять сторонних библиотек: NumPy, pandas, pydantic, PyYAML, Jinja2.
- **Российские нормы.** Самооценка по 25 процессам ГОСТ Р 56939-2024, нормы об ИИ и персональных данных ([docs/compliance/](docs/compliance/)).
- **DFIR.** Аналитик отмечает технику MITRE ATT&CK найденной атаки — отчёт показывает, какие техники автоматика закрывает без человека.

## Чего «Лимен» не делает

- не стоит в потоке алертов и ничего не закрывает сам;
- не подключается к SIEM, SOAR и другим системам по сети;
- не ставит метки: атаку от не-атаки отличают аналитики заказчика;
- не обещает качество на будущее: граница относится к проверенному периоду и потоку.

## Как проходит аудит

| Шаг | Что происходит | Чем |
|---|---|---|
| 1 | Параметры аудита фиксируются до выгрузки | `limen config-hash pilot.yaml` → протокол пилота |
| 2 | Проверка выгрузки: отличимо ли автозакрытие от ручного, есть ли вердикты | `limen validate` |
| 3 | Приведение к общей схеме, обезличивание учёток, хостов и адресов ключом заказчика | `limen keygen`, `limen prepare` |
| 4 | План выборки с фиксированным зерном, шаблон и офлайн-страница разметки | `limen plan --page-out labeling.html` |
| 5 | Перепроверка выборки аналитиками в браузере, без сети | `labeling.html` → `labels.csv` |
| 6 | Границы по потоку и по правилам, проверка, отчёт, метрики | `limen estimate`, `verify`, `report`, `metrics` |

Порядок пилота — [docs/pilot-protocol.md](docs/pilot-protocol.md).

## Режимы поставки

| Режим | Что покидает контур заказчика | Как |
|---|---|---|
| Строгий | только отчёт с агрегатами | заказчик запускает «Лимен» у себя: контейнер без сети или установка ролью Ansible из локальных колёс |
| Основной | минимальная таблица: псевдоним алерта, правило, источник, время и причина закрытия, вердикт, score | `limen export-minimal`; план и метки переводятся между псевдонимами и исходными ID командой `limen translate-ids` |
| Партнёрский | решает партнёр | перепроверку как свою услугу проводит MSSP или лицензиат, «Лимен» даёт методику и расчёт |

## Быстрый старт

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
make install   # окружение: ядро и инструменты разработки
make lock      # uv.lock и requirements/*.txt с хешами — один раз после клонирования
make hooks     # git-хук: запрет данных и ключей, Ruff, поиск секретов
make test      # тесты
make demo      # сквозной прогон на синтетике → data/demo/report.html и labeling.html
```

## Команды

| Команда | Назначение |
|---|---|
| `limen config-hash` | SHA-256 параметров аудита для протокола пилота |
| `limen keygen` | ключ обезличивания (32 случайных байта, права 600); остаётся у заказчика |
| `limen validate` | проверка выгрузки; код выхода 2, если аудит невозможен |
| `limen prepare` | маппинг полей, удаление дублей, обезличивание |
| `limen export-minimal` | минимальная таблица для основного режима |
| `limen translate-ids` | перевод `alert_id` между псевдонимами и исходными ID (только внутри контура) |
| `limen plan` | план выборки с хешами входов, шаблон и офлайн-страница разметки |
| `limen labeling-page` | офлайн-страница по готовому шаблону |
| `limen estimate` | границы доли атак и FNR, решения по правилам; код 3 при нарушении целостности |
| `limen verify` | сверка хешей входов и пересчёт результата |
| `limen report` | отчёт в Markdown или HTML |
| `limen metrics` | метрики для Prometheus (textfile collector) |
| `limen bound` | граница по одним счётчикам, например `--n 300 --k 0 --population 12400 --attacks-open 400` |
| `limen sample-size` | сколько алертов перепроверить, чтобы граница не превысила порог |

У всех команд есть `--audit-log` — журнал действий в JSON Lines для SIEM заказчика.

## Проверки и безопасная разработка

| Проверка | Команда | В CI |
|---|---|---|
| Ruff: стиль, правила Pylint и безопасности | `make lint` | `lint` |
| mypy, строгий режим | `make typecheck` | `typecheck` |
| PyTest с покрытием | `make cov` | `test` |
| SonarQube (SAST) | `make sast` | `sast-sonarqube` |
| Trivy: зависимости, секреты, конфигурации, SBOM | `make security` | `sca`, `secrets-scan`, `misconfig`, `sbom` |
| Trivy: образ | `make image-scan` | `image-scan` |
| Учёт уязвимостей в DefectDojo | — | `defectdojo` |

Секреты конвейера выдаёт Vault по JWT задания; образ публикуется в Harbor только после сканирования. Соответствие процессам ГОСТ Р 56939-2024 — [docs/compliance/gost-r-56939-2024.md](docs/compliance/gost-r-56939-2024.md).

## Сборка и развёртывание

```bash
make image                    # колёса из исходников, установка без индекса пакетов
docker compose run --rm audit validate data/raw/export.csv \
    --mapping configs/mappings/generic_csv.yaml        # без сети; точка входа образа — limen
make trivy-build              # Trivy из исходников (TRIVY_VERSION, TRIVY_COMMIT)
```

Контейнер работает от пользователя с uid 10001: каталогам `data/` и `reports/` на хосте нужны права на запись для него. Установка на изолированный хост — роль Ansible в `deploy/ansible/`; мониторинг между аудитами — `deploy/monitoring/` (правила Alertmanager и панель Grafana).

## Исследование на открытых данных

Гипотезы H1 (границы не занижают истинную долю пропущенных атак) и H2 (активная выборка сужает границу при том же бюджете) проверяются на наборе Microsoft GUIDE. Протокол — [docs/research-protocol.md](docs/research-protocol.md), данные — [data/README.md](data/README.md).

```bash
make install-research
python -m limen.research run --config configs/experiments/guide_smoke.yaml   # отладка
dvc repro                                                                   # полный протокол по dvc.yaml
```

С переменной `LIMEN_MLFLOW_URI` (например, `file:./mlruns`) параметры и результаты пишутся в MLflow.

## Состояние

Версия 0.2.0 — каркас MVP, изменения — в [CHANGELOG.md](CHANGELOG.md). Расчёт границ, планы выборки, конвейер аудита, командная строка, контроль целостности, офлайн-страница и метрики покрыты тестами на синтетических данных. На реальных выгрузках не проверено: в маппинге KUMA есть поля с пометкой «ПРОВЕРИТЬ». Сборка образа, задания CI, роль Ansible, правила Prometheus и панель Grafana написаны, но в среде разработки каркаса не запускались. Схема `active` пока даёт только приближённую границу. Экспериментов на GUIDE ещё не было.

Лицензия не выбрана — см. [docs/compliance/law.md](docs/compliance/law.md).
