# ИИ: законы, приказы и ГОСТ

## Где в «Лимен» есть ИИ

- **Ядро не содержит моделей машинного обучения.** Оно считает статистические границы по случайной выборке; решения принимают аналитики заказчика, а «Лимен» только измеряет, сколько атак автоматика закрыла без человека.
- **Объект аудита — чужая автоматизация**, часто построенная на ИИ: модули автоматического закрытия у вендоров SIEM и SOAR.
- **Модель есть только в исследовательском контуре**: CatBoost изображает автоматизацию вендора в симуляции на открытом наборе GUIDE ([карточка модели](../model-card.md)). Заказчику она не поставляется.

## Что в «Лимен» уже работает на доверие к ИИ

- Граница ошибок автоматики держится на случайной выборке, а не на заявлениях вендора или на качестве его модели.
- Метки ставят люди; ответ «не знаю» считается атакой — консервативно.
- Известные ограничения записаны и проверяются тестами: схема `active` даёт приближённую границу и помечена предупреждением ([методика](../methodology.md#известная-проблема-схемы-active)).
- Каждый результат воспроизводим и проверяем: хеши входов, `limen verify`, зёрна выборки, журнал действий.
- Для модели исследовательского контура есть карточка модели, для данных заказчика — карточка выгрузки ([data-card-guide.md](../data-card-guide.md)).
