# Модель угроз

Модель описывает версию 0.2: командную строку, офлайн-страницу разметки, метрики, конвейер сборки и исследовательский контур. Пересматривается при каждом изменении режимов поставки, форматов данных или зависимостей. Процесс соответствует п. 5.7 ГОСТ Р 56939-2024 ([карта процессов](compliance/gost-r-56939-2024.md)).

## Что защищаем

| Актив | Где | Чем ценен |
|---|---|---|
| Выгрузка закрытых алертов | у заказчика | учётные записи, хосты, адреса, сведения о работе SOC; персональные данные в широком смысле закона № 152-ФЗ |
| Ключ обезличивания | у заказчика (`secrets/`) | позволяет связать псевдонимы с исходными значениями |
| Таблица соответствия псевдонимов | у заказчика, если создана | прямая расшифровка псевдонимов |
| Минимальная таблица (основной режим) | у исполнителя | правила, время закрытия, вердикты — сведения о настройке SOC |
| План выборки и метки | у того, кто считает | от них зависит итог аудита |
| Результат, отчёт, метрики | у заказчика | вывод о надёжности автоматизации, основание для решений |
| Исходный код, зависимости, образ | GitLab, Harbor | от них зависит всё остальное |

## Поверхность атаки

- **Входные файлы**: выгрузка (CSV, JSON, JSONL), YAML-конфигурации, план, метки, результат.
- **Офлайн-страница разметки**: HTML-файл с данными выборки, открывается в браузере аналитика.
- **Командная строка**: аргументы и переменные окружения (`LIMEN_PSEUDO_KEY_FILE`, `LIMEN_AUDIT_LOG`).
- **Цепочка поставок**: исходные дистрибутивы пакетов, базовые образы, инструменты CI, исходный код Trivy.
- Сетевых интерфейсов у ядра нет: ни открытых портов, ни исходящих соединений.

## Границы доверия

1. **Контур заказчика** — выгрузка, ключ, исходные `alert_id`, таблица соответствия, рабочие места аналитиков.
2. **Исполнитель** — в основном режиме получает только минимальную таблицу и метки с псевдонимами.
3. **Конвейер сборки** — GitLab, раннеры CI, Harbor, Vault.

## Угрозы и меры

| № | Угроза | Мера в версии 0.2 | Остаточный риск |
|---|---|---|---|
| У1 | Утечка исходной выгрузки за контур | Строгий режим: всё считается у заказчика. Основной: наружу уходит только `minimal_export`. Контейнер аудита без сети | ошибка оператора при выборе файла; нужен чек-лист передачи |
| У2 | Повторная идентификация по псевдонимам | HMAC-SHA256 с секретным ключом: без ключа перебор по словарю логинов не работает; псевдонимы сущностей в минимальную таблицу не входят | время закрытия и правило позволяют найти алерт тому, у кого есть доступ к SIEM заказчика, то есть самому заказчику |
| У3 | Компрометация ключа | права 600; `secrets/` исключён из Git и образа; монтируется только для чтения; новый ключ на каждый аудит; в журнал ключ не пишется | нет хранения в HSM; Vault Agent у заказчика — рекомендация, не часть «Лимен» |
| У4 | Подгонка выборки под желаемый итог | зерно, бюджет и схема фиксируются в протоколе до выгрузки; в плане — SHA-256 таблицы и параметров; `estimate` останавливается при несовпадении | подпись плана отсутствует; сверка хешей с протоколом — ручная |
| У5 | Подмена таблицы, плана или меток | SHA-256 всех входов в результате; `limen verify` сверяет хеши и пересчитывает итог; журнал действий | нет электронной подписи файлов |
| У6 | Ошибочные метки | инструкция для аналитиков; «не знаю» и неразмеченные считаются атакой | пропущенная при перепроверке атака занижает границу; повторная независимая разметка части выборки пока ручная |
| У7 | Внедрение кода через данные алерта на странице разметки | значения выводятся через `textContent`; JSON в странице экранирует `<`, `>` и `&`; CSP разрешает только встроенные скрипт и стили по SHA-256 | старые браузеры без поддержки CSP; рекомендуется актуальный браузер |
| У8 | Вывод данных со страницы разметки наружу | CSP: `connect-src 'none'`, `form-action 'none'`, `img-src 'none'` | данные остаются в localStorage браузера аналитика до очистки |
| У9 | Формульная инъекция в CSV, открытых в Excel | текст полей, начинающийся с `=`, `+`, `-`, `@`, табуляции или возврата каретки, получает префикс-апостроф — в шаблоне и в выгрузке меток со страницы | другие табличные редакторы могут обрабатывать ввод иначе |
| У10 | Внедрение кода в HTML-отчёт через названия правил | шаблоны `*.html.j2` с автоэкранированием Jinja2; `StrictUndefined` | Markdown-отчёт не экранируется: при показе в веб-просмотрщике полагаемся на его экранирование |
| У11 | Вредоносные файлы конфигурации и выгрузки | `yaml.safe_load`; pydantic с запретом лишних ключей; pickle не используется | ошибки разбора в pandas; запускать на файлах из доверенного источника |
| У12 | Скомпрометированные зависимости | хеши в `uv.lock` и `requirements/*.txt`; сборка ядра из исходников; Trivy SCA и SBOM в CI; DefectDojo | зависимости самой сборки ставятся без проверки хешей ([ADR 0003](adr/0003-build-from-source.md)) |
| У13 | Подменённый инструмент проверки | Trivy собирается из исходников с проверкой коммита тега; `GOTOOLCHAIN=local` | SonarScanner и базовые образы — готовые, закрепляются по digest в Harbor |
| У14 | Утечка секретов конвейера | Vault выдаёт секреты по JWT задания; поиск секретов Trivy в CI и git-хуке | токен SonarQube — переменная CI, ограниченная одним проектом |
| У15 | Данные заказчика в репозитории | `.gitignore`, git-хук запрещает `data/`, `secrets/`, `reports/` и файлы ключей | хук работает, только если подключён (`make hooks`); в CI дублирует поиск секретов |
| У16 | Ложный вывод «можно автоматизировать» из-за множества правил | параметр `simultaneous_rules`; отчёт называет маргинальные границы маргинальными | пользователь может не включить поправку |
| У17 | Вывод по схеме с приближённой гарантией | результат помечается `finite_sample_valid = false`; командная строка предупреждает о схеме `active`; правило Alertmanager `LimenApproximateBound` | предупреждение можно проигнорировать |

## Что не рассматривается

- Компрометация рабочих станций и серверов заказчика: это зона его собственной защиты.
- Злонамеренный заказчик, искажающий собственную выгрузку: аудит проверяет автоматизацию по данным заказчика и не защищает от подделки этих данных.

## Что сделать до первого платного пилота

1. `make lock` и сборка образа в CI; закрепление базовых образов по digest в Harbor.
2. Контрольные суммы плана и меток в протоколе пилота; позже — электронная подпись.
3. Чек-лист передачи файлов в основном режиме.
4. Внешний просмотр модели угроз специалистом ИБ заказчика.
