# Методика расчёта

Документ описывает, что именно считает «Лимен», при каких допущениях границы корректны и где гарантия только приближённая. Формулы совпадают с кодом в `src/limen/stats/` и `src/limen/audit/`.

## Обозначения

За период аудита:

- N_C — число алертов, закрытых без аналитика (источники из `audited_sources`, по умолчанию `auto` и `suppression`);
- A_C — число атак среди них; оно неизвестно, его и оцениваем;
- A_O — число атак, которые нашли аналитики среди алертов, закрытых вручную; известно из вердиктов;
- n — размер выборки для перепроверки, k — число атак в ней;
- 1 − δ — уверенность, по умолчанию 0,95.

```math
\mathrm{FOR} = \frac{A_C}{N_C}, \qquad \mathrm{FNR} = \frac{A_C}{A_C + A_O}
```

FNR здесь — доля атак, закрытых автоматикой, среди атак, по которым был алерт. Атаки, на которые SIEM не создал алерта, в эту величину не входят: это вопрос покрытия правилами корреляции, а не автозакрытия.

## Равномерная выборка (`uniform`)

Из N_C автозакрытых алертов без возвращения отбираются n. Верхняя граница доли атак — односторонняя граница Клоппера–Пирсона:

```math
p_U = B^{-1}\left(1-\delta;\ k+1,\ n-k\right), \qquad k < n,
```

где B⁻¹ — квантиль бета-распределения. При k = 0 она упрощается до p_U = 1 − δ^{1/n}. Покрытие не ниже 1 − δ при любом n; для выборки без возвращения биномиальная граница консервативна.

Граница числа атак U = p_U · N_C. При `bound_method: hypergeometric` U — наибольшее M, при котором P(X ≤ k) ≥ δ для гипергеометрической X с параметрами (N_C, M, n). Она уже биномиальной, когда выборка составляет заметную долю N_C.

Сколько перепроверить при уверенности 95%:

| Порог доли атак | 0 атак в выборке | 1 атака | 2 атаки |
|---|---:|---:|---:|
| 1% | 299 | 473 | 628 |
| 2% | 149 | 236 | 313 |
| 5% | 59 | 93 | 124 |

Столбец «0 атак» — n = ⌈ln δ / ln(1 − p)⌉; остальные — наименьшее n, при котором p_U(k, n) не превышает порог. Те же числа даёт `limen sample-size --target 0.01 --k 1`.

## От доли атак к доле пропущенных атак

FNR = A_C / (A_C + A_O) монотонно растёт по A_C. Поэтому из A_C ≤ U с вероятностью не ниже 1 − δ следует с той же уверенностью

```math
\mathrm{FNR} \le \frac{U}{U + A_O}.
```

A_O берётся из вердиктов как известная величина.

**Пример.** N_C = 12 400, n = 300, k = 0, A_O = 400. Гипергеометрическая граница U = 121, то есть доля атак среди автозакрытых не больше 0,98%, а FNR ≤ 121 / (121 + 400) ≈ 23,2%. Низкая граница FOR ещё не значит, что автоматизация теряет мало атак: автозакрытых алертов здесь в 31 раз больше, чем атак, найденных аналитиками. Чтобы сузить границу FNR, нужна выборка больше или стратификация по правилам с большим объёмом автозакрытия. Проверка: `limen bound --n 300 --k 0 --population 12400 --attacks-open 400`.

## Границы по правилам

При равномерной выборке, а при стратифицированной — если страты совпадают с правилами (по умолчанию `stratum_column: rule_id`), отбор внутри правила при фиксированном n_h остаётся простой случайной выборкой. Поэтому граница Клоппера–Пирсона по каждому правилу корректна. Правило без выборки получает худший случай: все его автозакрытые алерты считаются атаками.

**Множественные сравнения.** При десятках правил хотя бы один ложный вывод «можно автоматизировать» вероятен, даже если каждая граница верна с уверенностью 1 − δ. Параметр `simultaneous_rules: true` включает поправку Бонферрони: каждая граница строится с уверенностью 1 − δ/R, где R — число правил, и тогда все границы верны одновременно с уверенностью не ниже 1 − δ. Без поправки отчёт прямо называет границы маргинальными.

**Решения.** Порог p₀ задаётся параметром `target_for`.

| Решение | Условие | Что делать |
|---|---|---|
| можно автоматизировать (`safe`) | верхняя граница ≤ p₀ | автозакрытие по правилу можно сохранять или расширять |
| теряет атаки (`leaks`) | односторонняя нижняя граница Клоппера–Пирсона > p₀ | исправить правило или отключить для него автозакрытие |
| мало данных (`insufficient`) | атак в выборке нет, но выборка мала | добрать выборку |
| неясно (`uncertain`) | атаки найдены, вывод неоднозначен | добрать выборку и разобрать найденные атаки |

«Добрать» — сколько ещё случайных алертов правила перепроверить, чтобы получить «можно автоматизировать», если новых атак не найдётся: n_required(p₀, k_h) − n_h.

Для схемы `active` отбор внутри правила неравновероятный, поэтому сырые k_h/n_h не используются: «можно автоматизировать» ставится, только если верхняя граница разностной оценки не выше p₀; вывод «теряет атаки» и размер добора не рассчитываются.

## Стратифицированная выборка (`stratified`)

Бюджет распределяется по стратам пропорционально числу автозакрытых алертов N_h. В программном интерфейсе доступно распределение по Нейману — пропорционально N_h·√(p_h(1 − p_h)), если известны априорные доли атак p_h. На каждую страту приходится не меньше `min_per_stratum` алертов; если минимум не помещается в бюджет, самые мелкие правила сливаются в страту `__other__`. Дробные части распределяются методом наибольших остатков.

Граница суммарного числа атак:

- `union` (по умолчанию) — δ делится поровну между H стратами, U = Σ_h N_h · p_U(k_h, n_h; 1 − δ/H). Корректна на конечной выборке по неравенству Буля, но консервативна при большом H;
- `korn_graubard` — граница Клоппера–Пирсона по эффективному размеру выборки n_eff = p̂(1 − p̂)/V̂(p̂), но не больше фактического размера выборки (Korn, Graubard, 1998). Она уже, но гарантия приближённая; её фактическое покрытие проверяется в H1. Страты без выборки учитываются худшим случаем.

## Активная выборка (`active`)

Для каждого автозакрытого алерта есть оценка модели f_i ∈ [0, 1]: score вендора или своей модели. Алерт попадает в выборку независимо от других с вероятностью π_i ∝ √(f_i(1 − f_i)) — чаще отбираются алерты, в которых модель не уверена. Сумма π_i равна бюджету, π_i ∈ [π_min, 1], где π_min = floor · n / N_C (по умолчанию floor = 0,2): нижняя граница не даёт весам 1/π_i стать огромными. Размер выборки случаен, его ожидание равно бюджету.

Разностная оценка числа атак и оценка её дисперсии:

```math
\hat A = \lambda \sum_{i=1}^{N_C} f_i + \sum_{i \in S} \frac{y_i - \lambda f_i}{\pi_i},
\qquad
\hat V = \sum_{i \in S} \frac{1-\pi_i}{\pi_i^{2}}\,\left(y_i - \lambda f_i\right)^{2}.
```

Оценка несмещённая при любой модели f; модель влияет только на дисперсию. При λ = 0 это оценка Хорвица–Томпсона, по умолчанию λ = 1. Граница U = Â + z_{1−δ}·√V̂ (не меньше числа найденных атак и не больше N_C) опирается на нормальное приближение, поэтому гарантия асимптотическая и результат помечается `finite_sample_valid = false`. При редких атаках нормальное приближение может давать покрытие ниже заявленного — это проверяет H1. Подход — active statistical inference (Zrnic, Candès, 2024); при равных π_i он совпадает с prediction-powered inference (Angelopoulos и др., 2023).

### Известная проблема схемы `active`

На синтетических совокупностях — от 900 до 20 000 автозакрытых алертов, 0,6–1,9% атак, хорошо откалиброванная модель, бюджет 150–300, floor 0,2, по 3 000 повторов отбора — нормальная граница накрыла истинное число атак в 75–88% повторов вместо заявленных 95%. Сама оценка при этом оставалась несмещённой, а граница Клоппера–Пирсона при равномерной выборке в тех же совокупностях накрыла истину в 96–100% повторов. Причина — редкость атак: если в выборку попало мало атак или ни одной, оценка дисперсии не видит главного источника разброса, и граница выходит слишком узкой.

Следствия:

- пока схема не исправлена, выводы по пилотам делаются по `uniform`; команды `plan` и `estimate` выводят предупреждение для `active`;
- тест `test_active_bound_coverage_with_rare_attacks` помечен как ожидаемо падающий (`xfail`, `strict`): когда граница станет корректной, он начнёт проходить и потребует снять пометку;
- кандидаты на замену — границы на основе тестовых супермартингалов («ставок»), корректные на конечной выборке и допускающие неравные вероятности отбора и использование оценок модели: ALPHA (Stark, 2022) и доверительные последовательности для выборки без возвращения (Waudby-Smith, Ramdas, 2020). Их нужно включить в H1 и H2 наравне с текущей схемой.

## Ответы «не знаю» и пропуски

- `as_attack` (по умолчанию): ответ «не знаю» и неразмеченный отобранный алерт считаются атакой. Граница остаётся корректной, но становится шире.
- `exclude`: такие алерты исключаются из выборки. Это корректно, только если пропуски не связаны с содержанием алерта; отчёт отмечает возможное смещение.

Заменять неразмеченный алерт другим нельзя: замена ломает случайность отбора.

## Допущения и ограничения

1. **Метка аналитика при перепроверке верна.** Если аналитик не распознал атаку, граница занижена. Риск снижают разбор в обычном режиме с доступом к SIEM и EDR, честное «не знаю» и повторная независимая разметка части выборки (в версии 0.2 не реализована).
2. **A_O полно и верно:** все атаки, найденные аналитиками за период, отмечены вердиктом.
3. **Источник закрытия определён верно.** Если часть автозакрытий выглядит в выгрузке как ручные, они не попадут в аудит.
4. **Выборка проведена по плану:** размечены все отобранные алерты, без замен и выбора «удобных».
5. **Граница относится к периоду выгрузки.** Если изменились правила, модель вендора или поток, нужен новый аудит; динамику показывает страница «Мониторинг».
6. **Единица анализа — алерт.** Если автоматика закрывает алерты целыми инцидентами, оценка по инцидентам потребует в выгрузке идентификатора инцидента; в версии 0.2 её нет.

## Как это вычисляется

Ядро не зависит от SciPy ([ADR 0002](adr/0002-course-stack.md)). Нужные функции реализованы в `src/limen/stats/special.py` на стандартной библиотеке Python:

- регуляризованная неполная бета-функция I_x(a, b) — непрерывной дробью (модифицированный метод Лентца, Numerical Recipes, § 6.4);
- обратная к ней — методом Ньютона с защитой бисекцией; через неё считаются границы Клоппера–Пирсона и граница Корна–Граубарда;
- биномиальная функция распределения — через I_x(a, b); размер выборки `n_required` ищется по ней напрямую: граница Клоппера–Пирсона не выше порога ровно тогда, когда P(X ≤ k | n, порог) ≤ δ;
- гипергеометрическая функция распределения — суммой членов через логарифмы гамма-функции;
- квантиль нормального распределения — `statistics.NormalDist`.

Тесты `tests/test_special.py` сверяют эти функции с точными рациональными вычислениями и со SciPy; относительная погрешность на проверочной сетке — порядка 10⁻¹¹.

## Почему не конформные методы

Conformal risk control (Angelopoulos и др., 2024) контролирует ожидаемое значение потерь, а Learn then Test (Angelopoulos и др., 2021) с заданной вероятностью ограничивает риск порога, выбранного на калибровочных данных. Обе процедуры отвечают на вопрос «какой порог модели выбрать». Аудит отвечает на другой вопрос — сколько атак уже оказалось в конкретном множестве закрытых алертов, — поэтому здесь применяется теория выборочных обследований конечной совокупности. Learn then Test может понадобиться позже, если «Лимен» начнёт рекомендовать порог автозакрытия.
