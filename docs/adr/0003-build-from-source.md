# ADR 0003. Сборка из исходников и границы доверия цепочки поставок

- Статус: принято
- Дата: 30.10.2026

## Контекст

- Готовые бинарные пакеты и образы — непрозрачная часть цепочки поставок: проверить, что бинарный файл собран из опубликованного кода, на практике нельзя.
- ГОСТ Р 56939-2024 выделяет безопасную систему сборки, безопасность сборочной среды и проверку цепочек поставок (п. 5.12, 5.13, 5.17).
- Полная сборка всего из исходников, включая компиляторы, uv, Ruff и сам Python, для одного разработчика неподъёмна. Нужна явная граница.

## Решение

Из исходников собирается то, что попадает к заказчику или принимает решения о доверии:

1. **Зависимости ядра** — в сборочном этапе `Dockerfile`: `PIP_NO_BINARY=:all:`, проверка SHA-256 каждого исходного дистрибутива по `requirements/runtime.txt`, компиляторы и системные библиотеки — из пакетов ОС базового образа (`toolchain/python-wheels/build-wheels.sh`).
2. **Сам «Лимен»** — колесо собирается из исходников тем же этапом; рабочий образ ставит пакеты только из собранных колёс, без индекса (`PIP_NO_INDEX=1`).
3. **Trivy** — из тега исходного кода с проверкой SHA коммита (`toolchain/trivy/`); `GOTOOLCHAIN=local` запрещает Go скачивать другой компилятор, модули проверяются по `go.sum`.

Остальное фиксируется по хешам, но не собирается из исходников:

- инструменты разработки (Ruff, mypy, PyTest и др.) — из `requirements/dev.txt` с проверкой хешей;
- uv — на рабочем месте разработчика, в CI не используется;
- базовые образы (Python, Go, Debian), SonarScanner, Docker — из Harbor с закреплением по digest.

Якоря доверия: репозиторий пакетов ОС базового образа, исходные дистрибутивы с хешами из `uv.lock`, теги исходного кода с проверенными коммитами.

## Последствия

- Сборка образа долгая: компилируются NumPy, pandas и pydantic-core (Rust). Колёса стоит кэшировать в CI.
- **Остаточный риск.** pip ставит зависимости самой сборки (setuptools, meson-python, Cython, maturin и т. п.) в изолированное окружение без проверки хешей. Их источником должен быть доверенный репозиторий; следующий шаг — закрепить их версии файлом ограничений и собирать в окружении без доступа к внешней сети.
- **Не проверено в среде разработки каркаса**: там нет доступа к индексу пакетов и демону Docker. Первая сборка в CI может потребовать правок списка системных пакетов (например, версии Rust для pydantic-core).

## Рассмотренные варианты

- **Готовые колёса с проверкой хешей.** Проще и быстрее, но бинарный код остаётся непроверяемым. Допустимо для разработки, не для поставки.
- **Всё из исходников, включая инструменты разработки.** Отклонено как непропорциональное для одного разработчика; вернуться при сертификации.
