# ADR 0002. Стек из курсов автора и минимум зависимостей в ядре

- Статус: принято
- Дата: 30.10.2026

## Контекст

- Проект ведёт один человек. Инструменты, которые он уже знает по курсам DevOps, DevSecOps и MLOps, быстрее внедрить и проще поддерживать, чем новые.
- Каждая зависимость ядра попадает в контур заказчика, проходит проверку ИБ и собирается из исходников ([ADR 0003](0003-build-from-source.md)). Чем зависимостей меньше, тем дешевле и сборка, и проверка.
- В версии 0.1 были Typer, Streamlit, pyarrow и SciPy в ядре, а также gitleaks, pip-audit и фреймворк pre-commit в процессе разработки. Их нет в программах курсов автора.

## Решение

1. Инструменты берутся из курсов. Всё остальное помечается в [docs/stack.md](../stack.md) как «вариант» с причиной выбора.
2. Командная строка — argparse из стандартной библиотеки вместо Typer.
3. Разметка — офлайн-страница на шаблоне Jinja2 вместо сервера Streamlit; мониторинг — Prometheus, Grafana и Alertmanager через файл метрик.
4. Хранение промежуточных таблиц — CSV вместо Parquet: убирает pyarrow и делает файлы читаемыми для проверки ИБ заказчика.
5. SciPy выводится из ядра: нужные функции (неполная бета-функция и обратная к ней, гипергеометрическая функция распределения, квантиль нормального распределения) реализованы на стандартной библиотеке и сверяются со SciPy в тестах. SciPy остаётся в исследовательском контуре.
6. Проверки безопасности — Trivy (уязвимости, секреты, конфигурации, SBOM) и SonarQube; учёт уязвимостей — DefectDojo; секреты конвейера — Vault; git-хук — на Bash без внешних фреймворков.

## Последствия

- Ядро зависит от пяти библиотек: NumPy, pandas, pydantic, PyYAML, Jinja2.
- Командную строку и страницу разметки можно тестировать без дополнительных пакетов; страница проверена в браузере под политикой CSP.
- Свои реализации специальных функций — новый код, требующий проверки. Её дают сверка со SciPy, точные рациональные вычисления в тестах и известные значения (299, 149, 59 и др.).
- Статистика Streamlit «из коробки» потеряна: мониторинг теперь требует Prometheus и Grafana у заказчика.

## Рассмотренные варианты

- **Оставить стек версии 0.1.** Отклонено: больше зависимостей в контуре заказчика и инструменты вне опыта автора.
- **Убрать и pydantic, заменив его dataclasses.** Отложено: pydantic есть в курсе MLOps и надёжно проверяет конфигурации; цена — Rust-компонент pydantic-core при сборке из исходников.
