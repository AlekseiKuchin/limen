# ADR 0001. Офлайн по умолчанию

- Статус: принято
- Дата: 27.10.2026, уточнено 30.10.2026 (версия 0.2: офлайн-страница вместо Streamlit, метрики через файл)

## Контекст

- Выгрузка закрытых алертов содержит учётные записи, имена хостов, адреса и сведения о настройке SOC. Для заказчика это чувствительные данные, а часть из них — персональные.
- Первые заказчики — SOC и MSSP, в том числе обслуживающие КИИ, банки и госсектор. Любое внешнее ПО в их контуре проходит проверку ИБ; сетевые вызовы и передача данных наружу эту проверку осложняют или делают невозможной.
- Проект ведёт один человек без бюджета: облачный сервис с защитой персональных данных и аттестацией ему сейчас не по силам.
- Задача аудита не требует связи с внешним миром: всё считается по выгрузке за период и по меткам аналитиков.

## Решение

1. Ядро «Лимен» не делает сетевых вызовов: в его зависимостях нет сетевых библиотек, а тест `test_no_network` падает, если такой импорт появится.
2. Вход и выход — файлы: выгрузка и конфигурация на входе, план, результат и отчёт на выходе.
3. Контейнер для аудита запускается без сети (`network_mode: none`), с файловой системой только для чтения и без Linux capabilities.
4. Разметка — офлайн-страница: один HTML-файл без сервера; политика CSP запрещает ей внешние запросы.
5. Мониторинг — файл метрик для textfile collector node_exporter: у «Лимен» нет открытых портов.
6. MLflow, CatBoost и SciPy используются только в исследовательском контуре и не входят в ядро; логирование в MLflow включается лишь явной переменной `LIMEN_MLFLOW_URI`.
7. В основном режиме поставки за контур уходит только минимальная таблица; в строгом — ничего, кроме отчёта.

## Последствия

Плюсы:

- проще согласование с ИБ заказчика: исходники короткие, сетевых вызовов нет, данные не уходят;
- работает в изолированных сегментах;
- нет облачной инфраструктуры, которую нужно защищать и оплачивать.

Минусы:

- выгрузку заказчик делает сам, и её качество зависит от него;
- мониторинг между аудитами не непрерывный: каждый аудит запускается заново по новой выгрузке;
- нет телеметрии использования — обратная связь только из интервью и пилотов;
- обновления доставляются вручную.

## Рассмотренные варианты

- **Облачный сервис.** Отклонён: передача персональных данных и сведений о SOC за контур, требования к защите и доверие заказчиков несовместимы с ресурсами проекта.
- **Агент с подключением к API SIEM внутри контура.** Отложен: нужна отдельная интеграция с каждым продуктом и более глубокая проверка ИБ. Вернуться, когда появятся повторные аудиты у одного заказчика и будет понятно, какие интеграции нужнее.
