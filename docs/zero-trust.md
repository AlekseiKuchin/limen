# Нулевое доверие

Принципы взяты из NIST SP 800-207 «Zero Trust Architecture» (2020): не доверять по умолчанию ни сети, ни файлу, ни пользователю; проверять явно каждое обращение; давать минимальные права; исходить из того, что компрометация уже возможна. Для офлайн-утилиты, которая работает с чувствительными данными SOC, они превращаются в конкретные правила.

## Файлы на границе контура не принимаются на веру

| Переход | Проверка | Где |
|---|---|---|
| выгрузка → таблица алертов | схема маппинга (pydantic, лишние ключи запрещены), стоп-критерии `validate` | `config.py`, `io/validation.py` |
| таблица алертов → план | в план записываются SHA-256 таблицы и параметров аудита | `audit/pipeline.py` |
| план и метки → расчёт | `estimate` останавливается с кодом 3, если таблица алертов не та или параметры изменились без `--allow-config-change` | `cli.py`, `integrity.py` |
| метки аналитиков | допустимы только `attack`, `benign`, `unknown`; техника ATT&CK — по шаблону `T1234` или `T1234.001` | `audit/labels.py` |
| результат → заказчик | в результате — SHA-256 всех входов; `limen verify` сверяет хеши и заново выполняет расчёт | `cli.py` |

## Минимальные права

- Ядро не открывает сетевых соединений: в нём нет сетевых библиотек, это проверяет `tests/test_no_network.py`.
- Контейнер аудита: без сети, без root (uid 10001), корневая ФС только для чтения, без Linux capabilities, `no-new-privileges`; каталог с ключом смонтирован только для чтения.
- Установка на хост ролью Ansible: отдельный системный пользователь без входа в систему, каталоги данных с правами `0700`, установка только из локальных колёс без доступа к индексу пакетов.
- В конвейере CI пароли Harbor и ключ DefectDojo выдаёт Vault на время задания по JWT, а не хранятся в переменных; токен SonarQube ограничен анализом одного проекта.

## Утечка невозможна даже при ошибке

- Офлайн-страница разметки работает под политикой Content-Security-Policy: разрешены только встроенные скрипт и стили по их SHA-256, `connect-src 'none'`, `form-action 'none'`. Даже если в данные алерта попадёт вредоносный текст, страница не сможет ни выполнить его, ни отправить данные: значения выводятся как текст, внешние запросы запрещены.
- Учётки, хосты и адреса обезличиваются ключом заказчика сразу после чтения выгрузки; в основном режиме наружу уходит только минимальная таблица.
- Отчёт и метрики содержат только агрегаты.

## Предполагаем компрометацию

- Журнал действий в JSON Lines (`--audit-log`, `LIMEN_AUDIT_LOG`) — кто, когда, с какими хешами входов и выходов выполнил команду. Журнал уходит в SIEM заказчика и помогает разобрать инцидент.
- На каждый аудит — новый ключ обезличивания: псевдонимы разных аудитов нельзя связать.
- Метрики пишутся в файл и читаются node_exporter на той же машине: у «Лимен» нет открытых портов.

## Цепочка поставок

- Все зависимости зафиксированы в `uv.lock` и `requirements/*.txt` с SHA-256.
- Зависимости ядра собираются из исходников внутри сборочного образа, установка в рабочий образ идёт без индекса пакетов.
- Trivy, которым проверяется всё остальное, собирается из исходников с проверкой коммита тега.
- Границы этого подхода и оставшиеся риски — [ADR 0003](adr/0003-build-from-source.md).
